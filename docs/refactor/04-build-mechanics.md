# 構築（Build）機制：學習 D2 Survivors（待選）

接續 [03-gameplay-direction.md](03-gameplay-direction.md)（那份的 B「職業與天賦」與 A 的進化相關部分，以這份為準）。
使用者要學的是 D2 Survivors 的 **build 機制**（角色靠技能、被動、進化、修飾組出流派）。本文沒有改任何程式。

## D2 Survivors 的構築機制（來源與可信度）

來源是社群整理的第三方資料站（[技能與進化](https://d2survivors.net/skills/)、[野蠻人構築路線](https://d2survivors.net/builds/barbarian/)、[構築總覽](https://d2survivors.net/builds/)），
頁面自己標明「細節是單一來源、未獨立驗證」，且幾個網域引用不同版本。**以下是各頁明寫的內容，不是我玩過的結論。**

| 項目 | 資料站寫的 |
|---|---|
| 開局 | 一場從沒有技能開始；1 級給三張卡，**每個技能樹各一張**，選一張 |
| 升級 | 每升一級三張卡；重抽、跳過、放逐各 2 次（營地鐵匠 Charsi 每次升級 +1，最多 5） |
| 欄位 | 一般難度 6 個技能＋6 個被動；噩夢以上 8＋8；打過 Baal 後各 +2 |
| 進化 | 技能升到最高級 ＋ 持有該技能的「觸媒」被動（有等級要求）＋角色等級達標；**由下一個寶箱觸發**，不是升級卡 |
| 多段進化 | 進化後的技能從 1 級重新累積，要新的觸媒與寶箱才能再進化一次（例：火焰彈 → 火球 → 流星） |
| 修飾 | 技能修飾可隨時編輯（每職業最多 10 個）；Boss 掉落，機率 1.2%，連續沒掉會逐步提高（保底） |
| 重選第一招 | 營地 NPC 或「赦免令牌」（都要先打過 Baal），或開新一場 |
| 其他 | 技能無魔力消耗；有構築規劃器工具 |

野蠻人的路線範例（頁面表格）：雙擊（觸媒：加速）→ 狂亂（角色 24 級）；猛擊（觸媒：斧精通）→ 集中（18 級）→（觸媒：鐵甲）→ 狂戰（30 級）；吶喊（觸媒：活力）→ 戰鬥號令（24 級）→（觸媒：尋寶）→ 戰鬥統帥（30 級）。
頁面沒寫的：各進化的詳細數值、同階的具體傷害、防禦技能何時補（只給「先把輸出建好再補生存」的建議）。

## 我們現有的對應（盤點自 `data/game.json` 與 `main.gd`）

| D2 Survivors | 我們已有 | 差距 |
|---|---|---|
| 升級三選一卡 | 有（升級抽卡，`pending_cards`） | 相同 |
| 重抽、放逐 | 有（`Save.rerolls()`，營地建築可加次數；截圖基準裡也有放逐畫面） | 相同；可再加「跳過」 |
| 技能被觸媒進化 | 有：同伴 Lv5 且持有指定果子 → 進化（`_ready_evolutions`、「進化！」卡） | **只有單段**；沒有「寶箱觸發」；沒有多段 |
| 欄位上限 | 同伴人數有上限（`Save.party_cap()`） | 沒有「技能欄 ＋ 被動欄」兩個上限 |
| 技能樹各給一張的開局 | 領袖（9 位）各有技能組（`kits`）；同伴有流派標籤 | 沒有「開局從三個流派各抽一張」的選擇 |
| 修飾 | 恩賜盤（局外天賦盤）、局內天賦 | 沒有「Boss 掉的、可編輯的技能修飾」 |
| 重選第一招 | 開新一場 | 沒有局外的重選工具 |
| 構築規劃器 | 圖鑑有進化清單 | 沒有「路線預覽」介面 |

## 提案（由小到大，可單獨砍）

1. **多段進化鏈**（建議第一個做）：進化資料加 `next`，進化後同伴從 1 級重新累積，要新的果子（觸媒）才能再進化一次。改動集中在進化資料與 `_ready_evolutions`／`_evolve`。
2. **寶箱觸發進化**：進化條件達成後由下一個寶箱觸發（像 D2S），讓寶箱成為構築的轉折點；現有「寶箱與進化」段已把兩者放在一起，改動小。
3. **欄位上限**：同伴（技能）與果子（被動）各自有上限，逼玩家取捨；數字待平衡腳本決定。
4. **開局三選一**：1 級從三個流派各抽一張，取代現在的開局方式（先要確認現有 1 級流程，這項需要先讀 `_ready` 與開局邏輯）。
5. **Boss 掉修飾**：接到裝備詞綴系統（03 的 A2）：Boss 小機率掉「技能修飾」，帶保底。
6. **路線預覽**：圖鑑加「進化路線」頁，顯示基礎、觸媒、等級條件（等於 D2S 的規劃器簡化版）。

## 限制與風險

- 存檔：封閉測試中不必顧相容（使用者 2026-11-08 指示），可直接加欄位；改格式時重產 `tests/unit/save/` 黃金樣本。
- 平衡：多段進化與欄位上限會大幅改變強度曲線，要先建立新的 storysim 基準，並加平衡檢查。
- 教學：依 CLAUDE.md Rule 15，每個新機制都要補聚焦式教學步驟（`data-tour`）。
- 智慧財產：只學機制，不用暗黑的名稱、美術、音效；技能與進化名稱沿用我們的使徒行傳主題。
- 資料可信度：D2S 的數字與規則來自單一來源，**不要照抄數值**，只學結構。
